# Exhaustive state keys and cross-batch sharing

Research date: 2026-11-18. Scope: existing local sources only; no upstream investigation, implementation changes, tests or benchmarks. Recommendations below are unvalidated designs unless explicitly identified as current behavior.

## Exactness contract

The target is grouped ordinary/default-calibration M4A1 `18010000001`, Detonation (`bd`), recoil preset, budget 800, Insight `13110000091` locked at `11`, no dominance and unchanged grouping/exclusions. Every original legal grouped layout must either receive its exact native score or inherit it through a proved equivalence; preserve its identity and rank position. Expected original population is **12,885,654**, with **64,429** retained rows (`ceil(N/200)`). This count is an acceptance expectation from prior evidence, not remeasured here. The existing report explicitly distinguishes this population from its dominance-reduced 1,696,710 paths and 8,484 survivors ([report:28-32](m4a1_merged_ranked_screening.md#L28)).

For two prefixes at the same decision layer, merging requires: identical legal remaining labeled choices and native operation order; identical score/validity behavior for each common suffix; identical budget feasibility; complete correlated incoming identity paths; exact multiplicity. A suffix class is reusable only under the same requirements. Different identities remain separate ranked rows even if their scores coincide. No score bound, shortlist or dominance rule may remove a path. Existing identity reconstruction and mass checks implement the relevant provenance pattern ([merged_screening.mjs:92-111](../tools/merged_screening.mjs#L92)).

## Current source evidence

The latest local module rejects `experimental_dominance=true`, no longer imports or invokes the reducer, and reports `dominance_enabled:false` ([merged_screening.mjs:22-25](../tools/merged_screening.mjs#L22), [79](../tools/merged_screening.mjs#L79)). This source review uses shared-source cache v2; historical reduced-domain results cited below do not describe the active policy.

The key is full pre-mapping numeric buckets, ordered replacement tokens, sensitive item occurrences and cost. Numeric buckets retain `initial`, `addend`, `multA`, `multC`; serialization distinguishes undefined and negative zero and rejects nonfinite values ([merged_screening.mjs:12-15](../tools/merged_screening.mjs#L12), [35-39](../tools/merged_screening.mjs#L35)). Equal keys are used only inside identical continuation shapes. Native interleaving, nested providers, coupling, occupancy, devices and bound ammo trigger conservative fallback ([42-65](../tools/merged_screening.mjs#L42)). Shapes retain paths, ordered options and bundled defaults; they intentionally omit host identity only for empty tuning ([60-62](../tools/merged_screening.mjs#L60)).

Planning groups shapes, sorts root keys, then splits into batches of at most 16 prefixes ([69-79](../tools/merged_screening.mjs#L69)). Expansion and state maps are batch-local ([87-103](../tools/merged_screening.mjs#L87)). The scorer cache survives jobs within a screening instance, but its caches describe operation sequences, not globally equivalent final numerical states ([shared_stats.mjs:3-9](../tools/shared_stats.mjs#L3), [53-64](../tools/shared_stats.mjs#L53)). Consequently equal numerical states reached through different batches or operation sequences can still be scored repeatedly. The observed report explicitly calls its result batch-limited ([report:48](m4a1_merged_ranked_screening.md#L48)). This demonstrates an opportunity, not its size on the original domain.

Recoil ranking uses strict recoil then Handling, and chart mode computes a 20-point trajectory and fastest horizontal speed ([optimizer_presets.mjs:54-87](../tools/optimizer_presets.mjs#L54)). Timing is a live dependency: `timedRecoil` obtains calculated RPM, resolves source fire-control from applied IDs and numeric timing, and advances each point using source intervals ([timed_recoil.mjs:26-54](../tools/timed_recoil.mjs#L26)). Dropping fire-rate effects because they do not change spatial recoil multipliers would change speed-tier loss.

The minified native source is legitimately one long line: named functions below make its line citations auditable. `F` folds raw buckets and propagates `SprintToFireSpeed` and main-attribute direct rules; `L` maps main attributes into targets; `P` resolves replacement references in source order; `A` evaluates buckets; `G`, `z`, `q` resolve item-sensitive firing schedules and SDK timing ([kernel.mjs:2](../.scratch/calibration-check/kernel.mjs#L2)). The exported state contract exposes these native functions ([kernel.mjs:6](../.scratch/calibration-check/kernel.mjs#L6)). Native attribute `f` constructs recoil trajectories; `p` checks all required profiles before computing output and fire rate ([attributes.mjs:1](../.scratch/calibration-check/attributes.mjs#L1)). The chart contract exports the actual trajectory implementation ([attributes.mjs:3](../.scratch/calibration-check/attributes.mjs#L3)).

## Smaller proved keys

### Stage 1: resolved reference state

Replace the entire replacement-token history with the resolved reference fields required by subsequent evaluation, initially retaining **all** native reference fields. Native `P` is an ordered deterministic reference-state update, so equal resolved reference state followed by identical replacements has identical reference outcomes. Keep separate source-order/native-validation evidence: changing the key must not require histories to match once equivalence has been proved. The current terminal guard compares full replacement histories ([merged_screening.mjs:108](../tools/merged_screening.mjs#L108)); it must be revised deliberately for this equivalence, not bypassed accidentally.

This is a source-supported proof direction, not a measured reduction. It requires exposing/certifying the reference transition function and fixed weapon/mode/base context. Do not resolve references by sorting replacement tokens. Last writers and target/mode-dependent interpretation matter (`P`, [kernel.mjs:2](../.scratch/calibration-check/kernel.mjs#L2)).

### Stage 2: live-target projection

Introduce a versioned certificate owned jointly by scorer and native runtime:

`compileLiveStateContract({packHash, runtimeHashes, preset, mode, request, shape, layer}) -> {contextKey, bucketTargets, referenceFields, identityState, validate, project, advance}`.

`project` must encode retained raw bucket components with exact Number semantics. `advance` must use original native order and the native fold; never reassociate additions or products. A certificate mismatch or unknown dependency uses the existing full key/fallback. The certificate is a correctness capability, not a user-selected approximation.

For chart recoil the initial output dependency set includes `GRecoil_H`, `GRecoil_V`, `GRecoil_HShake`, `GRecoil_VShake`, `GGunkickRandom`, `GGunkickSpring`, `GAiming_ADSTime`, `GSprintToFireTime`; ADS recoil/aiming references and fire-control state are also live ([optimizer_presets.mjs:54-80](../tools/optimizer_presets.mjs#L54)). Include all timing reads in native `H/q/G` and the calculated-RPM path, including special-fire overrides/prerequisites/order ([kernel.mjs:2](../.scratch/calibration-check/kernel.mjs#L2), [timed_recoil.mjs:29-44](../tools/timed_recoil.mjs#L29)). Treat this as a starting set, not a complete certified manifest.

Compute backward dependency closure through native numeric aliases/direct rules, curve mappings, base-target/reference selection and chart generation. If a live mapped target depends on main attribute 3 or 5, retain that main-attribute raw bucket even if the main attribute is not itself emitted. Include all mappings that can overwrite or accumulate into a live target in their original order. Display-only attributes, damage, range, reload and magazine effects are candidates for omission from score keys only after this closure and validity contract establishes their irrelevance for this fixture. `abstractProfile:true` bypasses the magazine capacity comparison for ranking, but does not bypass native calculation and profile validation ([optimizer_presets.mjs:61](../tools/optimizer_presets.mjs#L61), [timed_recoil.mjs:42](../tools/timed_recoil.mjs#L42)).

A conservative layer-independent closure is easiest to certify first. Later layer-specific backward analysis can forget state killed by a guaranteed future write, but only if every allowed continuation kills it and no earlier dependent read/validity check occurs. Current numeric `Initial` changes only `initial`, not the other bucket fields (`k`, [kernel.mjs:2](../.scratch/calibration-check/kernel.mjs#L2)); it does not kill the entire bucket. Final scalar equality is insufficient at intermediate layers: a future Addend can distinguish equal scalars with different multiplicative components. Even final projection should preferably preserve raw live buckets and native calculation rather than invent a second scorer.

Keep cost in the initial prefix key: it determines remaining feasible suffixes and ranking. Moving cost to a separate weighted distribution is possible but requires per-cost feasibility and row costs, not choosing the cheapest representative. Keep sensitive identity state until its complete behavior is certified. Current IDs cover coupling and special-fire overrides/unmodeled items ([merged_screening.mjs:29-32](../tools/merged_screening.mjs#L29)); a generalized certificate must also account for override `requiresItemIds` and selected-order behavior (`z`, [kernel.mjs:2](../.scratch/calibration-check/kernel.mjs#L2)).

## Cross-batch and cross-worker sharing

Implement in increasing complexity:

1. **Bounded persistent terminal memo.** Reuse the current strong terminal key plus pack/runtime/preset/request/context versions across jobs handled by one worker. Cache objective vector and score only; each caller supplies its own cost/signature and emits every alias. Preserve native validity checks per complete layout context or a proved validity-equivalent class. This removes repeated scoring without changing traversal/provenance. A worker-local byte-capped LRU is a safe first implementation: eviction means recomputation. Cache hit count and avoided native score count must be distinguished from layout count.
2. **Stable ownership for terminal scoring.** Route full exact terminal keys to one of 16 compute workers using a hash only for routing, compare canonical key bytes for equality. Send bounded request batches, use backpressure, and memoize completed results within a byte cap; in-flight deduplication avoids simultaneous duplicate scoring. Return results to every requesting provenance batch. The coordinator need not retain all keys. Include retained key bytes and pending requests in the cap; on saturation score locally or recompute, never discard a request. No speedup is guaranteed: message copying and imbalance may outweigh reuse.
3. **Global layer frontier sharing.** To avoid repeated suffix expansion, intern `(contextKey, continuationShape, layer, exactStateKey)` across batches, keeping incoming paths in a separate provenance graph. Each unique state expands once; all incoming arcs retain labels and BigInt path mass. Score terminal states once, then reconstruct aliases for ranking. This is a global extension of the current layered DAG, not a union of independent per-slot choices. It requires a layer barrier or equivalent delta propagation: a node expanded before later arrivals cannot silently lose incoming mass.

For bounded Node memory, use external-memory layer processing. Partition frontier records among the same 16 owners by canonical-key hash; spill byte-capped sorted runs to task-local files, externally merge by full key, append provenance edges to files, and stream each distinct state through expansion. Store immutable IDs/offsets rather than entire prefix configurations per edge. Retain only current run buffers, bounded open files, bounded outbound queues, scorer caches and top-K heaps. Persist BigInt mass as exact decimal/binary integers. Disk budget/exhaustion must produce a clear incomplete run or explicit exhaustive recomputation, never a successful truncated population. No disk or memory bound implies a runtime bound.

A simpler bounded RAM alternative is to keep shape cohorts intact when possible, retain cross-batch terminal memo, and accept repeated suffix work when a cap is hit. This preserves exhaustiveness and is easier to validate. Expanding all cohorts together without spill is unsafe operationally given the reported 5.86 GiB process RSS on the reduced-domain run ([report:20](m4a1_merged_ranked_screening.md#L20)). The byte limits suggested here are design requirements, not measured sizing recommendations. Browser/Pages cannot assume shared memory or Node filesystem spill; defer browser design or use bounded recomputation until a separate storage contract exists.

Memoization of a suffix **operation list** or transition program is also safe when it applies operations in native order to each incoming state; it saves collection/dispatch but does not prove equal scores. Do not replace arbitrary suffixes by summed modifiers or multiplied aggregate coefficients: floating-point operation order and mappings make algebraic equivalence insufficient. Identical suffix shape alone does not justify equal scores; incoming live state, budget and semantic context are essential.

## Required validation before exactness claims

All later tests/measurements must use **16 actual participating workers**; none were run in this research. Parent-owned validation should first establish dominance disabled in both planner and counter, unchanged grouping, N=12,885,654, K=64,429, and no score pruning. Capture source hashes and explicit runtime/scorer certificate versions.

Validate each key relaxation independently against full native uncached evaluation and the existing strong key. Include adversarial cases for last-writer replacements, negative zero, nonfinite rejection, equal current scalars/different raw buckets, mapped main attributes, timing-driven horizontal speed thresholds, special-fire prerequisites/order, defaults, source interleaving, budget boundaries and alias ties. Unknown capabilities must fall back conservatively.

For the full original fixture compare every canonical identity/objective/score/cost manifest against a no-dominance exhaustive control, per-partition counts and global sums, exact survivor arrays/order/uniqueness, and fresh uncached native replay of all 64,429 survivors. Require BigInt mass equals reconstructed identities and no overlaps/gaps across partitions. Run cache-off, tiny-cap eviction, cross-owner duplicates, forced spill, partial result failures and cancellation/recovery paths; caps must alter only work/memory, not manifests. Separate scoring-call savings, unique states, transition work, aliases emitted and selection/reconstruction cost. Do not infer an under-one-million result or wall-time improvement from the existing reduced-domain run.

## Recommendation and uncertainty

Start with bounded persistent terminal memo using the existing full key; then resolved-reference keys and a certified conservative live-target projection. Pursue global external-memory frontier sharing only after measuring repeated states and proving its expected savings justify provenance/spill complexity. None of the proposed reductions has been measured on the original population. Cross-batch sharing is structurally available; its magnitude and whether it reaches fewer than one million scored states remain hypotheses.
