## Bipods: the concrete policy gap

`builder/app.js` maps socket **10** to Rail bipod, **36** to Barrel bipod, **31** to Side sight, and **45** to Lens hood. At the start of this audit, `tools/choice_groups.mjs` excluded automatic choices whose path contains 10/31/45; dedicated rail bipods already disappeared, but dedicated barrel bipods did not. The follow-up adds36. A read-only census of all 69 generated packs finds these socket-option IDs:

- Socket10: `13170000001`, `13170000002`, `13170000003`, `13170000004`, `13170000009`, `13170000010`, `13170000011`, `13170000012`, `13170000013`, `13170000015`.
- Socket36: `13170000005` (AUG Bipod), `13170000008` (AK-12 Bipod).

The safe snapshot-backed dedicated-bipod predicate is `path.split('/').some(segment => ['10','36'].includes(segment))`, with the existing ancestor-lock exemption: preserve a path if any fixed row equals that path or descends from it. Apply uniformly in option enumeration, compiled model constraints and normalization, as existing `excluded` does. Use actual socket identity rather than translated names, item-ID prefixes or effects. A lock on a provider ancestor alone does not lock every optional child; a fixed bipod or descendant must preserve its ancestor chain. An explicitly forbidden locked part must be rejected clearly if the intended policy is absolute prohibition; silently deleting a user lock is incorrect. Existing project convention is automatic exclusion with exact locks preserved.

M4A1 `18010000001` contains `13170000004` through socket10 and has no socket36, so adding36 alone cannot reduce this fixture's current grouped ordinary population. Default/forced mounts need separate attention: `tools/optimized_exact_dag.mjs:describe` retains a mounted default even when `groups.options` is empty, and source `tools/scip_mount_model.mjs` distinguishes user/default/forced mounting. Disabling optional picks cannot authorize removing a forced source dependency. A policy that forbids every mounted bipod must verify default omission is source legal or exclude its provider; do not assert that filtering selectable IDs guarantees no default bipod.

`translation/translations.json` also names **Collapsible Bipod Grip `13140000038`**, **AK-12 Elite Bipod Long Barrel `13020000370`**, **AUG Elite Bipod Long Barrel `13020000367`**, and **M249 Bipod Handguard `13050000325`**. These are grip/barrel/handguard choices, not dedicated socket10/36 attachments. M4A1 includes grip `13140000038`. A broad request to prohibit any bipod-bearing component must explicitly include these IDs through a documented catalog classification; name matching is incomplete (several dedicated IDs lack English translations), translation-dependent and can discard substantial ordinary stats/provider structure. Dedicated-bipod exclusion does not establish that hybrids are useless. Source identities and translated names are evidence of classification, not current-client behavior verification.

## Exact reductions worth implementing next

1. **Normalize continuation programs independently of labels.** `tools/optimized_exact_dag.mjs:describe` interns each choice as `['c', e.path, choices.map(c => [c.choice,c.cost,c.block?.id])]`; both path and concrete item identity therefore fragment otherwise identical numeric transition programs. Keep native event sequence, exact operation blocks, costs, legal option correspondence and default replacement behavior, but represent choice labels through a per-root/per-edge mapping in provenance. Canonicalize transition domains only when a bijection preserves legality and labels can be reconstructed. Do not merge root programs solely because they have the same numeric terminal scores. `createProvenance` in `tools/exact_dag_storage.mjs` already retains correlated paths and BigInt mass, but path remapping is a new proof obligation.

2. **Remove dead operations before interning blocks/programs.** `tools/exact_recoil_scorer.mjs` derives `liveTargets` from explicit objective/timing reads plus main-attribute curve dependencies. `optimized_exact_dag.mjs:stateKey` already ignores globally dead numeric buckets, yet `block.id` includes *all* operation targets, and continuation IDs therefore retain differences with no consumer. Build a certified projection for transition signatures that removes writes outside the transitive closure of score, references, future legality, cost, floors and tuning consumers. The current exact DAG rejects floors and tuning, providing a narrow starting certificate. Preserve unknown operations and reference replacements conservatively. This can share transitions/programs without discarding a single identity.

3. **Stage-specific forward liveness, with a qualification.** Current keys retain every globally live bucket at every layer. A bucket is dead at a boundary only if no continuation can observe its previous value before a definite overwrite. A subsequent Addend/Mult_A/Mult_C does not kill a prior bucket: all components can survive to finalization. An Initial write may replace only the initial component, leaving accumulated additive/multiplicative components live; inspect the native numeric reducer before declaring a whole-target kill. Use per-component backward dependency analysis over the native ordered suffix, including mapping/reference reads. Most recoil stats remain terminal consumers, so a large reduction is a hypothesis.

4. **Fold deterministic events and preserve identities for neutral branches.** Leading fixed events are already folded (`while ... kind==='fixed'` in `describe`). Interior fixed runs can become one ordered transition and contract frontier storage. A choice with the same numeric/cost transition as another can share one transition with multiple provenance labels/mass. A genuinely no-op option and empty/default may still differ in cost, identity, replacement of bundled defaults, calibration, child sockets, coupling or occupancy. Never delete such a rank position just because native default score is unchanged. `choice_groups.mjs` currently deliberately selects minimum-cost family representatives for established accessory equivalence; broadening that policy changes the enumerated population unless original aliases are retained explicitly. Fixed locks can remove the branching variable, while their cost/effects/source order remain.

5. **Exact-state rather than additive symmetry.** `choice_groups.mjs` permits patch count interchangeability only under its integer-add/tuning guards; tactical matching checks compatible socket assignments. General stocks/grips/barrels can carry decimal additions, multiplicative effects, tuning controls, providers and occupancy. IEEE754 accumulation is not associative; regrouping or sorting native operations can change a strict rank. Match full ordered operation behavior or exact resulting component buckets at a common continuation, preserving native order. Even identical operations on two sockets need compatible default-replacement and identity reconstruction. Exact keys in `exact_dag_storage.mjs` distinguish signed zero; any canonicalization must preserve the current exact numeric contract or prove observational equivalence.

## Follow-up: all-pack default and forced mounting census

Read-only traversal of every `assembly.coupling.*.rules` in all 69 generated packs finds exactly four rules targeting dedicated bipod sockets; all target10, none target36:

| Weapon | Condition | Bipod | Policy |
| --- | --- | --- | --- |
| RM277 `18010000049` | Barrel `13020000602` mounted | `13170000015` | forced |
| M249 `18040000002` | Handguard `13050000325` mounted | `13170000010` | forced |
| M250 `18040000003` | always | `13170000009` | default |
| Barrett M82 `18060000033` | Handguard `13050000393` or `13050000395` mounted | `13170000012` | default |

Crucial compiled-model behavior: `tools/scip_mount_model.mjs` adds both selectable options and coupling-mounted IDs to each slot's nodes, sets `node.active = equipped OR defaultMounted`, and accounts for extra occupancy before that union. `choice_groups.constrain` sets **all** excluded slot nodes' `active` to zero. Consequently the existing socket10 policy already prevents default/forced bipods in compiled allowed solutions, as well as purchases. It can make a provider choice unavailable or a request infeasible; it does not remove the bipod while leaving a source-illegal provider configuration. M250's unconditional default can require a legal occupying component to suppress its socket10 mount, if such a component is available. For example, source extra occupancy records for grips `13140000031` and `13140000038` include sockets10/36. This is a restriction of the allowed policy population and should be exposed as such, especially for locked providers. A lock on a provider does not exempt its bipod child; a lock on the child does exempt its own path and ancestor chain.

`options()`/normalization by themselves do not implement this default guarantee; paths relying on them without `constrain()` must check resolved mounted rows or share the compiled policy. `optimized_exact_dag.mjs` does apply `groups.constrain(compiled)` before enumeration, so its explicit retention of defaults in `describe` is not on its own a policy bypass.

Neither has a socket36 coupling default/forced rule. Check omitted automatic choice, exact explicit child lock preservation and unchanged source legality after policy filtering.
