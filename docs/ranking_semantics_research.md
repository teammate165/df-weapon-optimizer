## Implemented policy and validation

The reference exact gate now uses the shared [ranking contract](../tools/screening_rank.mjs): BigInt `ceil(N/200)` for both ordinary and per-base tactical screening; strict shortfall/objectives/cost/code-unit identity ordering, with version `exact-shortfall-objectives-cost-code-unit-signature-v1`. Canonical key sorting also uses code-unit comparison. Score pruning preserves this strict shortfall precedence and never prunes equal primary scores by a cost/signature assumption. Feasibility acceptance still uses the existing source-floor tolerance, separately from ordering.

This intentionally changes the treatment of near-equal values from the historical pairwise tolerance. It makes the exact gate's result independent of encounter order for a fixed, uniquely identified, finite scored population. It does not change the production anytime comparator or turn its shortlists into an exact percentile gate. SCIP response metadata and local study survivor estimates now report 0.5%; the study still retains only a best preview. Historical data files remain unchanged.

[16-worker validation](../data/optimizer_validation/ranking_20261118/validation.json) records every participating compute worker. Tests cover integer boundaries, huge BigInt counts, near-tie transitivity, an alias class crossing the cutoff, serial versus global-K shard selection with differing traversal orders, and the existing independent native two-stage suite (G18, both presets, all modes, locks, floors, source replay, mounting policies and SCIP membership) in each worker. The alias/shard checks use explicit synthetic rows; **a weighted DAG selector and distributed full M4A1 survivor set are not implemented or validated**. Reproduce with `node tests/screening_ranking_workers.mjs`.

[Native reference fixture counts and survivor counts](../data/optimizer_validation/ranking_20261118/native-reference.json) preserve the detailed report from worker 0; all 16 workers independently ran that suite. The follow-up run also checked the exported static ranking module and reduced-budget M4A1 study count metadata in every worker. ## Existing behavior and the denominator

[exhaustive_attachment_gate.mjs](../tools/exhaustive_attachment_gate.mjs) exports `gateFraction=.05`, but `retainBest` independently computes `(BigInt(count)+19n)/20n`. Changing the export alone changes diagnostics without changing selection. Each invocation counts the legal domain first, then scores and keeps that many rows in a bounded max-heap.

The ordinary stage disables unlocked tactical purchases and counts all remaining legal explicit mounting decisions. It deliberately does **not** apply minimum-stat floors there. Each retained ordinary base then receives its own tactical enumeration: ordinary purchases are fixed, and minimum-stat floors are applied by source evaluation before determining that base's denominator. Final complete survivors are deduplicated by configuration signature. Thus the second stage is a percentile **per base**, not a global percentile of all tactical completions; final deduplication does not retroactively change either denominator. Locks, budget, mode and catalog legality belong to each population definition. [Source](../tools/exhaustive_attachment_gate.mjs).

For the requested policy use integer arithmetic `K = (N + 199n) / 200n`, independently at both stages. Empty populations retain zero; every nonempty population retains at least one. Ordinary baseline N = 12,885,654 gives **K = 64,429**, versus 644,283 previously. The experimental dominance population N = 1,696,710 gives **8,484**, but this is a different percentile population. Those are arithmetic consequences of recorded counts, not a newly measured scan. [Recorded scope/counts](archive/m4a1_dominance_prototype.md).

[exhaustive_screening_study.mjs](../tools/exhaustive_screening_study.mjs) applies choice-group constraints before counting, optionally applies dominance, and partitions by explicit root barrel and stock choices. Its count report currently hardcodes `(total+19n)/20n`; its scan retains only a best preview, choosing by objectives alone, with first encounter winning ties. That preview is not an exact gate survivor set and does not implement the gate's cost/signature tie-breakers.

## A deterministic comparator is not yet a total order

The gate uses `comparator(minimums)`, followed by `signature.localeCompare` if neither row is better. Existing precedence is: summed floor shortfall (differences over 1e-8), lexicographic objective vector (per-component relative tolerance `1e-12 * max(1, abs(a), abs(b))`), lower cost, then configuration signature. Cost is null in Warfare and behaves as zero in the objective-tie cost comparison. `configKey` serializes path/item pairs sorted using `localeCompare`. [Policy](../tools/optimizer_policy.mjs), [gate](../tools/exhaustive_attachment_gate.mjs).

**This pairwise tolerance is not transitive.** For one objective, take a=0, b=0.75e-12, c=1.5e-12, equal costs and signatures ordered c,b,a. The objective comparator ties a/b and b/c, but ranks a before c. Signature fallback therefore ranks b before a, c before b and a before c: a cycle. This follows from the source formula; it was not executed as a test. Floor tolerance has the same structural issue. A heap/sort result can consequently depend on encounter order. Calling this an exact total order, or assuming distributed merging preserves its serial output, would overstate the guarantee.

Recommended **new explicit total-order contract**, versioned because boundary identities can change:

1. Compute finite native objective vectors and finite nonnegative floor violations using the pinned request/scorer. Apply existing feasibility acceptance separately where required.
2. Rank ascending by exact numeric floor violation, then exact lexicographic objective values, then numeric cost (normalize unavailable Warfare cost to zero).
3. Break remaining ties with a canonical full configuration key using a specified code-unit comparison, not locale-dependent collation. Reject duplicate keys or deduplicate by the declared population before counting. Normalize signed zero for rank comparison; reject nonfinite objective components.

If tolerance grouping is required, replace exact values with **fixed, request-wide deterministic bins** and compare bin integers; pairwise closeness cannot define equivalence classes. Specify bin origin/width and retain raw values for source replay. Either design is a behavior change and needs explicit rank-version metadata. To reproduce legacy output literally, retain its traversal/heap algorithm and encounter order; that limits safe parallel reduction and is not a new total-order guarantee.

## Grouped populations, aliases and multiplicity

[choice_groups.mjs](../tools/choice_groups.mjs) selects compatible minimum-cost representatives for eligible equal-operation sight/magwell families and minimum-cost tactical family/count assignments. It also excludes unlocked accessory sockets 10/31/45. These are search-domain semantics, not a lossless multiset encoding of all source identities: the API exposes neither alias lists nor path multiplicities. Equal effects can have different costs. A grouped percentile therefore means one vote per legal grouped configuration, whereas a concrete percentile gives every legal original configuration one vote. Do not silently switch between them.

Declare the intended baseline **after existing grouping/exclusions, before new partial-state merging** to preserve the measured 12,885,654 ordinary population. New exact merging then compresses its representation, preserving BigInt incoming-path multiplicity and actual correlated backpointers. N is the sum of terminal path weights, not the number of DAG nodes, equivalence classes or scored representatives. A class contributes multiple ranked rows; it can straddle K. Select exactly the first required alias identities under the total order, rather than retaining every boundary tie or one representative per class. Scores may be shared only where equivalence proves them equal; costs/floors and canonical identities still participate in rank. [Equivalence/reconstruction contract](partial_state_merging_research.md), [current gate identity](../tools/exhaustive_attachment_gate.mjs).

For a genuinely concrete pre-grouping percentile, separately construct concrete aliases, their actual costs, lock/legal mounting relations and ordered reconstruction. Multiplying current representative rows by a family size cannot recover differing costs, conditional availability or correlated socket matchings. This larger population is a separate requested product contract, not something current grouping already preserves.

Dominance cannot preserve the old percentile through weights alone: removed configurations can have different objective positions and tactical/tuning possibilities. A winner's integer weight does not encode those positions. Use alias-preserving equivalence on the chosen baseline, or retain sufficient discarded-score information with a valid cutoff proof. A top-0.5% gate on the dominance domain is legitimate only when labeled as such; it is not the baseline's original top-0.5%. [Study scope](../tools/exhaustive_screening_study.mjs), [dominance limits](archive/m4a1_dominance_prototype.md).

## Distributed exact top-K

With a proven total order and disjoint exhaustive partitions, count all partitions first and set **one global K**. Each partition may retain `min(K, N_i)` best rows; globally merge their union and retain K. Proof: any discarded local row already has at least K globally better rows in that same partition. Keeping `ceil(N_i/200)` per partition is insufficient: an unusually strong partition can supply more than its proportional allocation to the global K. Current barrel/stock partitions are a suitable disjoint ordinary split, but their best-only summaries are insufficient. [Partition definition](../tools/exhaustive_screening_study.mjs).

For weighted classes, local retention must cover the first K **ranked paths**, with boundary-alias enumeration, not K arbitrary representatives. A shared class spanning partitions must have disjoint path provenance or globally reconciled weights. For lower transfer memory, workers can expose ordered streams and the coordinator perform a K-way merge; workers still need exact local ordering, external storage or additional passes. Adaptive cutoffs are safe only with certified bounds covering the full rank key and strict handling of cutoff ties. Worker completion, cancellation, counts and retry ownership must reconcile before declaring exact completion. These recommendations derive from the ordering/partition invariants; no distributed gate is implemented here.

Tactical selection remains independent per retained ordinary base. Parallelize bases or partition one base's completion population, but use that base's own total and K. Global ordinary K and tactical K must not be mixed.

## Calibration and implementation recommendations

[scip_optimizer.mjs](../tools/scip_optimizer.mjs) passes complete survivor configurations as `candidateConfigs` to the calibration mounting model and accepts candidates only when their full `configKey` is allowed. Preserve these complete rows: independently unioning socket aliases can create configurations that never survived. A default-score-equivalent class may contain different legal tuning domains; reconstruct every selected alias for calibration unless tactical and complete tuning correspondence are separately certified. Narrowing the screen to 0.5% can discard the best calibrated build; SCIP optimality over its surviving domain does not prove global calibrated optimality.

Recommended implementation sequence:

1. Centralize the fraction as exact numerator/denominator 1/200 and use it for both retention and reporting. Update SCIP method/formulation/fraction metadata and study count fields; preserve historical 5% evidence unchanged.
2. Specify grouped baseline, default-calibration stages, floor behavior, total-order version and tie identity before implementing weighted DAG selection or distributed top-K.
3. Keep the dominance profile's population explicitly distinct. Record baseline path count, reduced represented classes and selected path count separately.
4. Validate serial/distributed/weighted survivor identities, tie-boundary classes, tactical per-base denominators, source reconstruction and calibrated alias correspondence using **16 actual workers** for every future test/measurement. No such validation was performed for this note.

The current production [anytime_optimizer.mjs](../tools/anytime_optimizer.mjs) uses fixed bounded score/diversity pools (256 ordinary, 16 tactical per base, 512 complete), reports `fraction:null`, and merges worker shortlists heuristically. It has neither an exhaustive denominator nor a certified global top-K; changing an exhaustive 5% constant does not change that production search into a percentile gate. Preserve that distinction in UI and reports.
