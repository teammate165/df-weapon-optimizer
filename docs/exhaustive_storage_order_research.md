# Exact exhaustive screening: compact storage, deferred identities and native ordering

2026-11-18. Source inspection and proposed designs only; no tests or benchmarks were run. This report concerns original grouped ordinary M4A1 `18010000001`, Detonation (`bd`), Lowest Recoil, budget 800, Insight 3/7 `13110000091` locked at root `11`, empty tuning and **no dominance**. The expected original population is 12,885,654 and exact top-0.5% capacity is 64,429. Recounting the current fixture and validating these designs remain required. Existing 1,696,710-path evidence is historical dominance-reduced evidence, not validation of this population ([previous report](m4a1_merged_ranked_screening.md), Population and ranking).

Every legal path must receive its exact source score directly or through proven default-state equivalence. None of the proposals uses score bounds, promising-build shortlists, a reduced choice domain or dominance. Selection after complete scoring is distinct from pruning layouts before scoring.

## Existing costs and constraints

The current DAG clones every bucket object and its Map on each nonempty operation append, appends replacement/identity arrays, sorts and JSON-serializes buckets, then JSON-serializes that string inside another key (`tools/merged_screening.mjs:13-15`, `:35-39`). Each node retains object incoming arcs, while every terminal class reconstructs and emits all aliases immediately (`:91-111`). Full manifests in the existing study deliberately include every identity; their reconstruction cost is part of that validation protocol, not necessarily a production ranking requirement ([previous report](m4a1_merged_ranked_screening.md), Validation and measurement design).

The native shared-stat evaluator already demonstrates a useful copy-on-write boundary: clone the Map but clone only buckets touched by a part; freeze shared bucket objects (`tools/shared_stats.mjs:25-30`, `:45-48`, `:85-90`). This is a directly reusable design pattern, not evidence that changing the DAG is already validated. Alias propagation can touch targets beyond an operation's literal target, so derive touched keys through the native numeric contract, as the existing part precomputation does, rather than assuming one target per operation.

## Compact representation

Start with copy-on-write buckets using the existing native contract. Precompute immutable operation blocks and their complete write sets. Copy a bucket only before its first write in a transition; leave ancestors immutable. Preserve operation application order exactly. A sparse persistent block representation is a later alternative if copying the outer Map remains costly.

Then assign stable request-local IDs to target names, exact bucket tuples, replacement-sequence nodes and sensitive-identity-sequence nodes. Store layer metadata and costs separately from numeric states. Interning keys must preserve the current undefined initial value, signed zero, finite IEEE-754 numbers and normalized absent/no-op buckets. `Float64Array` can preserve binary64 values, but undefined needs a separate presence bitmap. Do not use Float32 or decimal rounding. A hash table may locate candidate tuples; exact tuple equality must resolve collisions. Never treat an ordinary hash as the proof of equality. Retain current no-op normalization rules until a broader normalization is proved equivalent (`tools/merged_screening.mjs:13-15`).

Packed state tables can hold bucket-block ID, reference-chain ID, sensitive-identity-chain ID, cost and provenance node ID. Use Uint32 IDs only while representable and check growth; widen or shard before overflow. Purchase costs can use integer arrays only after verifying the entire request's costs are safe integers with safe total bounds. Otherwise retain the native Number representation. Keep path masses as BigInt: BigUint64Array silently wraps and is unsafe without a checked upper bound. Plain BigInt arrays are the simplest initial choice.

For provenance, store edge parent ID, choice-label ID, next-edge ID and a per-node head index in growable chunks. Avoid many tiny JS objects and repeated path strings. After building a layer, a compressed sparse row edge table permits contiguous traversal. Retain root configuration IDs and null/default distinction. Duplicate parent edges can be coalesced only with explicit multiplicity and reversible identity provenance; otherwise coalescing can lose distinct purchases or double-count paths. Release numeric frontiers after advancing the layer, while retaining compact ancestors needed by surviving provenance.

This reduces representation/allocation overhead. It does not itself prove fewer source-scored terminal states. It may permit larger cohorts than the current 16-root boundary (`tools/merged_screening.mjs:72-75`), enabling more sharing, but improvement magnitude is unmeasured. Cache limits must cause exact recomputation or spill, never removal of a legal path. Coordinate per-worker budgets because 16 individually bounded workers can still exhaust host memory.

## Defer alias reconstruction with exact weighted ranking

Use the existing total order: shortfall, objective vector, cost, then code-unit canonical signature (`tools/screening_rank.mjs:15-25`). In this no-floor fixture the first field is constant; the general record should still retain it. A terminal state contributes its exact BigInt incoming-path mass, not one representative vote. Class equivalence must prove that all these rank-prefix fields agree for every incoming path. The existing state includes cost and sensitive identities and checks native raw state, replacements and cost on a representative (`tools/merged_screening.mjs:29-39`, `:107-108`); those conditions remain mandatory.

A conservative two-stage algorithm avoids designing a complicated lazy identity iterator:

1. Score every terminal class exactly and retain/spill `(rank prefix, mass, provenance reference)` records. Sum masses and reconcile with the independent original-domain count.
2. Sort or externally merge by the strict rank prefix, excluding signature. Combine all equal-prefix records across every job and worker, summing masses as BigInt. Find the first prefix whose cumulative mass reaches K=64,429.
3. Reconstruct every identity in strictly better prefix blocks; their total is less than K. Reconstruct the boundary prefix group and select exactly the remaining number of smallest canonical signatures across the **whole** group. Sort all selected rows with the existing full comparator.

Sorting all terminal records can use bounded sorted runs and a coordinator merge. No score is skipped; storage pressure leads to disk runs or replay. A bounded identity heap of remaining boundary capacity is exact even if the boundary group is huge; it still traverses that group's identities. Future lazy lexicographic extraction could reduce that traversal but requires an additional proof, not just sorting incoming edge labels.

Canonical identity is JSON of pairs sorted by code-unit slot/item order (`tools/exhaustive_attachment_gate.mjs:10-11`). Native operation order and DAG decision order differ from this ordering. A root-first or reverse-backpointer traversal is not automatically signature sorted. Empty/default choices, shorter arrays, punctuation, escaped strings and comparison of encoded JSON rather than numeric item IDs matter. Keep the existing configKey/comparator as the authoritative oracle. A valid lazy algorithm could construct a trie over complete canonical signature tokens and use exact prefix-language feasibility queries into correlated provenance, but that is more work than boundary streaming and should follow measurement.

Do not reconstruct a Cartesian product of per-slot unions. Each incoming arc points to its own parent history; only complete connected root-to-terminal paths are legal identities (`tools/merged_screening.mjs:103`; `tools/scip_mount_model.mjs:93-108` protects the same correlation when handing survivors to calibration). Combining tied terminal classes preserves separate provenance until the final identity union. Deduplicate only if disjoint-path uniqueness is proved or an explicit duplicate check detects a representation bug; silently deduplicating would hide an incorrect population.

An alternative worker-local weighted selection must use global K in each disjoint shard, preserve the local boundary's identity information, and globally reconcile exact prefixes and identities. Taking 0.5% independently in each worker is incorrect. A globally merged sorted class stream is easier to audit. The existing heap currently consumes individual rows, so it cannot simply be offered one weighted representative (`tools/ranked_screening_heap.mjs:1-13`).

If validation retains the current full per-path manifests, stream those identities independently; deferred ranking alone will not eliminate that validation traversal. For production, native replay of every selected complete configuration and exact mass accounting remain necessary. Earlier discarded-score manifests cannot be replaced solely with a best-build comparison.

## Native-order DAG for former fallback paths

The historical reduced-domain run used fallback for 144,360 paths. This is **not** a verified original-domain fallback count. The source rejects any root after the first child (`tools/merged_screening.mjs:43-44`) because its current constructor appends every root first and then every child layer (`:63-64`, `:95-100`). Reordering arithmetic would be unsafe: floating addition/multiplication, initial assignments and ordered reference replacement are not generally commutative.

Replace the root-then-leaves assumption with a certified native event schedule. For a fixed structural prefix, extract the native mounted sequence and compile an interleaved sequence of deterministic root-operation events and child-choice events. At each child event, append exactly the chosen equipped item or source default's operations; at each fixed event append the actual root operations. Charge purchase cost once, retaining the default/equipped distinction. Build layer keys at the event program counter, not merely child-depth. Any final native guard failure still discards provisional output and exhaustively replays the whole batch.

A simple first version keeps roots in separate cohorts until they have compatible schedules and identical remaining deterministic events/domains. Different root states can merge after an interleaved root event if their complete raw state and remaining continuation interface match. If future root events differ, either include the full remaining fixed-event program ID in the state key or delay merging until their programs coincide. Merging equal current numeric states while forgetting different future fixed roots would cross-wire histories. This is the principal additional invariant beyond the existing shape key, which currently records only child slots/options/defaults (`:62`).

A more general event DAG can encode root choices as decisions alongside children, but it must carry complete residual mounting constraints, default/rule state, occupancy, conditional identities and future domains. The mount search's count cache explicitly retains complete residual Boolean policy rather than only feasibility intervals (`tools/mount_search.mjs:134-150`). The mount compiler symbolically unrolls conditional bundled providers and occupancy (`tools/scip_mount_model.mjs:49-90`); copying only visible socket domains would be insufficient.

For the first interleaving implementation retain all existing fallbacks for nested providers, live coupling/occupancy, device selectors and bound ammo (`tools/merged_screening.mjs:46-58`). Verify that every child choice in the proposed cohort leaves the event order stable; an order sampled only from the default root build is insufficient if a choice changes mounting. This targeted extension can remove the *interleaving-only* reason without claiming to support the other rejected features. Exactness does not require removing fallback: unsupported cases must remain complete native enumeration.

## Validation requirements and priority

All executable validation and measurements must use **16 actual compute workers** under the user's constraint; none was run for this report.

| Priority | Change | Required evidence before an exactness claim |
| --- | --- | --- |
| 1 | Native-contract copy-on-write, interned exact tuples, packed provenance | Immutable ancestors; exact keys including undefined/-0; collision/overflow handling; unchanged full identity/score manifests and BigInt masses |
| 2 | Deferred class-prefix ranking and boundary identity streaming | Whole original N=12,885,654; K=64,429; complete ordered survivors equal an independent flat/full-sort control; ties spanning classes, jobs and workers; fresh uncached native replay of every survivor |
| 3 | Certified interleaved event schedules | Default/equipped/order/replacement cases; every supported cohort's native state replay; batch guard recovery; original-domain fallback reason/path census; complete identity/score manifests equal flat control |
| 4 | Larger cohorts/external-memory frontiers or lazy boundary tries | Bounded total memory with 16 workers; identical rank/path proofs; measured classes, transitions, alias traversal, spill bytes, peak memory and phase wall time |

Measure generation, state folding, class scoring, provenance storage, ranking, reconstruction, native guard/replay and validation-manifest time separately. Report both class count and path count. Under-one-million unique scorer calls, lower memory and faster wall time are separate outcomes. The prior 5.86 GiB sampled RSS and 12.55% scoring reduction concern a different, dominance-reduced population ([previous report](m4a1_merged_ranked_screening.md), Completed 800-point result); they cannot establish expected gains here.
