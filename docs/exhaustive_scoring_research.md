# Exact scoring from accumulated state and trajectory reuse

Research date: 2026-11-18. This is local pinned-source analysis, not an implementation or performance result. No tests or benchmarks were run. Scope is original grouped ordinary M4A1 (`18010000001`), Detonation (`bd`), Lowest Recoil, 800 cap, Insight `13110000091` at root `11`, empty tuning, dominance disabled, exact top 0.5%. Every original layout must receive a direct score or a score established by exact equivalence. Score bounds, dominance deletion and heuristic shortlists are outside this proposal.

## What currently repeats

`tools/merged_screening.mjs:81` resolves a representative layout, checks its canonical identity/lock and cost, gets shared state and calls preset raw/score/objectives. Its terminal DAG loop (`:105`) has already accumulated native raw buckets, ordered replacement operations, special-fire identities and cost, but scores the first reconstructed alias through this full path and independently checks accumulated buckets against native collection. This guard is valuable evidence, but is repeated work once an accumulated-state scorer has separately been certified. Dominance is now disabled: the module rejects an explicit dominance request at `:22`, enumerates without dominance reduction (`:24-25,48`) and declares the original grouped population in plan metadata (`:79`). These policy edits are reflected in shared source cache v2.

`tools/shared_stats.mjs:66` already avoids some state recomputation, using bounded native-operation prefixes. It still collects per-occurrence operations, selects global nonstacking operations and walks a prefix trie for every resolved build (`:76-90`). Its result is accepted by `presets.recoil.raw` (`tools/optimizer_presets.mjs:53`), but the chart branch calls `timedRecoil` (`:60`). That calls the full attribute calculator and a separate `kernel.u` (`tools/timed_recoil.mjs:27-28`). The full calculator itself computes base and current attributes (`.scratch/calibration-check/attributes.mjs:1`, function `h`), and both invoke `kernel.u` (function `p`). Thus passing cached numeric state into `raw` does not remove the chart branch's rebuilds.

## Source calculation order that must be preserved

The generated runtime is minified; functions cited below reside on `.scratch/calibration-check/kernel.mjs:2`, `.scratch/calibration-check/curves.mjs:1`, and `.scratch/calibration-check/attributes.mjs:1`. Function names identify the owning expression within those long lines.

1. Resolve mounting first (`curves` function `v`, traversal `_`): defaults, forced mounts, conditional coupling, occupancy and native mounted order affect collected operations. Do not replace the mounted order with canonical slot sorting. The existing root-first DAG explicitly rejects interleaved mounting (`merged_screening.mjs:42-58`).
2. Kernel `N` collects weapon operations, exceptional stock-reference corrections, then each mounted part's operations and tune operations, and optional ammo, before global `nonstackLaserOperations`. Tactical and fire-control filters occur here. Empty tuning and no ammo are necessary restrictions for the current shared-state seam; any tuned velocity operation has a separate native fold in `R`.
3. Kernel `P` resolves base references and applies ordered replacements; later matching replacement wins. Ammo reference overrides occur afterward. `F` folds modifications in source order into `{initial,addend,multA,multC}`, including `GBullet_OnlyRange`/`SprintToFireSpeed` aliases and main-stat direct-rule targets. `A` evaluates `((initial-or-fallback)+addend)*(1+multA)*multC`. Reassociating addition or multiplication changes binary64 results. `initial` assignment is order sensitive.
4. `F` calculates main/display attributes 2 through 6. `I` resolves base targets from profiles. `L` walks main attributes 2 through 6 and each mapping in stored order, applying AbsoluteMapping, AbsoluteMappingThenScale, DeltaMapping, or DeltaMappingThenScale to a private bucket map. It uses `curves.r` interpolation, including cubic tangents and native zero/one-anchor selection. Do not map an already mapped bucket map again. `R.value` applies the separate tuned-velocity map outside the ordinary map.
5. The recoil raw scorer uses mapped state, resolved aiming profile and fixed weapon behavior. Camera is `Math.hypot(HShake,VShake)`; kick is `Math.hypot(random,spring)` with the exact `??1` defaults in the preset. ADS and sprint timing remain unrounded seconds from state values. The full public calculator rounds handling with `Math.fround`, floor and milliseconds; using those panel values for secondary Handling would change ranking (`optimizer_presets.mjs:7-10,75-86`; attributes function `p`).
6. Full attributes `p` computes legacy RPM via `kernel.s` ordered overrides and multiplicative legacy fire-rate factors, then `kernel.r`. `timedRecoil` computes its own fire control with `kernel.n(pack,state.appliedParts,rpm/baseRpm,null,kernel.t(pack,state.value))`. Preserve SDK timing, override requirement/order, supported modes, selected mode, schedule status, trigger delay and schedule policies. Native kernel functions `z/G/q/H` own these rules. Do not substitute displayed rounded RPM or assume M4A1 attachments cannot affect timing without checking actual inputs.
7. Attribute trajectory `f` receives the resolved ADS recoil profile, automatic horizontal and vertical scales, single-only selector, and 20 shots. It chooses continuous vs single fallback, profile/loop arrays, independent H/V scales, initial length and loop period, accumulates `value*scale*axis/10` in order, and rounds each output through native `kernel.d(...,5)`. **`preservePrecision:true` does not disable this trajectory rounding:** `p` calls `f` without its sixth precision argument. Reusing an unrounded/scaled unit trajectory would change exact values and potentially the speed tier.
8. `timedRecoil` accumulates intervals sequentially using `curves.u({...fc,fireRate:rpm},shotIndex)` and starts at time zero. It requires modeled Auto and allowed schedule rules; abstract-profile mode waives capacity only. Source-path count and positive finite intervals remain checked.
9. Preset chart raw uses max absolute post-shot x (origin excluded from the list), max y minus min y, and `fastestHorizontalSpeed` over a 200 ms window. That function's interpolation, candidate starts, ascending iteration and strict `>` tie handling must remain exact (`tools/horizontal_speed.mjs:2-28`). Apply thresholds `>3`, `>4`, `>5`, then `vertical + multiplier*horizontal`. Compute normalized weighted loss in the existing `Object.entries(weights)` insertion order, including zero-weight branches and denominator reduction, then Handling (`optimizer_presets.mjs:63-86`). Do not replace divisions with precomputed reciprocals or algebraically flatten the weighted sum.

## Proposed API seam

Add a distinct pinned native contract consumer, conceptually `evaluateDefaultState({rawNumeric,orderedReferenceOps,appliedParts,context})`, then `scoreDefaultState(state)`. This is a proposal, not an existing API. Raw numeric input must carry main/display attributes calculated by native `F`, or produce them with native `F(pack,[],privateClone)` before mapping. Resolve native references/targets, clone only writable buckets, call native mapped function once and construct native-shaped value access. Expose a read-only core for recoil scoring; identities, canonical signature, cost, lock/mount validity and multiplicity remain per-layout outputs.

Directly pass terminal `state.buckets` from the DAG rather than reconstructing numeric state from a representative config. Keep fallback scoring for native order, tactical-selector or other unsupported contexts. The existing state key includes raw buckets, references, identities and cost (`merged_screening.mjs:34-39`); maintain those distinctions until a narrower dependency contract is validated. `shared_stats.mjs:53-64` supplies an existing exact mapping/reference implementation pattern, but its private `core` cannot currently be called from externally accumulated buckets.

For chart evaluation call the *actual* `calculate.screeningChartContract.trajectory`, with the same arguments as source attributes, then the existing timing/speed functions. `prepare_project_runtime.py:52-61` exposes it only for a SHA-pinned attribute module; state access is separately SHA/policy pinned (`:7-14,34-50`). Check function identities and versions as `scoring_bounds.mjs:27-29` does, and fall back on contract absence/change. Preserve missing-profile/protocol errors: the full attributes calculator requires bullet, movement, aiming, waist spread/recoil and ADS spread/recoil profiles before producing a result. A fast route must not quietly score a candidate the reference rejects.

`createRecoilScreeningBound` is useful source reconstruction evidence (`tools/scoring_bounds.mjs:40-69`), **not** a callable exact scorer. It subtracts an epsilon guard, omits Handling and deliberately publishes no exact score. Extracting a shared native chart helper is plausible; consuming its `lower` result would violate exhaustive ranking. Keep `boundCannotBeat` and all cutoff behavior out of the exhaustive scan.

## Exact cache domains and policy

Prefer layered worker-local caches scoped to immutable pack/runtime/mode/context and preset normalization. No cross-run reuse without pack content/revision, source/policy versions, request firing mode, tuning/ammo/tactical context and trajectory count identity. Use typed finite-number encoding that distinguishes signed zero, undefined/null, strings and arrays; `scoring_bounds.mjs:14-24` is an existing example. Never round keys, use epsilon equality or trust a hash without exact collision verification.

* Geometry cache: resolved ADS profile identity **within immutable pack**, automatic H/V binary64 values, actual single-selector boolean, count 20, native precision/rounding mode and trajectory contract identity. Profile id alone is insufficient across mutable packs. Cache source-rounded coordinate arrays, not a rescaled template.
* Timing cache: exact legacy RPM and all actual source `curves.u` inputs (supported/selected modes, schedule rules in order, their numbers/flags and defaults). Safest initial key is full native fire-control object plus RPM, count and curves runtime identity. Reuse a finished time vector only if generated by the identical sequential additions. Kernel override identities/requirements are upstream dependencies: compute native override/fc resolution first or retain their ordered applied-part dependency signature in an earlier cache.
* Pattern cache: geometry key plus timing key plus 200 ms window and exact speed implementation/version. Cache pattern and diagnostics if diagnostic identity is promised. `scoring_bounds.mjs:55` already groups primary objective by ADS profile, H/V, full timeline, camera and kick; its lowered value must not be reused as score.
* Objective cache: pattern/camera/kick plus raw ADS and sprint seconds, all baseline components, ordered weights, preset/runtime identity and score/model eligibility. Handling **must** be part of a full-objective key. Cost and canonical layout identity need not be in a numeric-objective key, but must still be evaluated/ranked for every represented path. Stat floors are absent in this fixture; a generalized route must keep them independent or include all required stat dependencies.

Bound each cache by entry count and key/payload bytes, retain counters for entries, bytes, misses, hits, evictions and disabled/fallback cases. FIFO or LRU affects performance only if eviction causes recomputation, never dropped layouts. Existing shared-stat caches stop admitting entries when saturated (`shared_stats.mjs:87-88`); source-bound cache evicts oldest entries (`scoring_bounds.mjs:34-37`). Measure either policy. Avoid global all-layout trajectory storage; preserve independent worker ownership and immutable cached arrays. An unresolved cache key must trigger direct scoring rather than reuse.

## Validation and profiling handoff

All subsequent validation/measurements must use **16 actual participating workers**, per current user requirement. The proposed route is unvalidated. Parent task owns execution.

First certify native-state and chart seams against fresh uncached native evaluation: exact numeric state, ordered reference resolution, applied override behavior, raw components/diagnostics, objective vector and error behavior. Exercise zero/signed-zero and mapping boundaries, replace order, coupled/default mounts, nonstacking, SDK timing and schedule changes, short magazines under abstract mode, invalid profiles and unsupported contracts. Force cache hits, eviction and disabled caches. Compare exact values rather than decimal tolerances; explicitly decide whether signed-zero diagnostics require `Object.is`.

Then reconcile original no-dominance grouped population and per-job counts; every layout must be directly scored or represented by documented equal-input class with BigInt path mass and reconstructed canonical identity. Compare complete sorted objective/cost/identity manifests and exact top `ceil(N/200)` survivor order with the no-dominance native reference. Replay survivors fresh and uncached, including secondary Handling and canonical boundary ties. Ordinary default proof does not certify calibrated/tactical aliases.

Profile separately: mount resolution; operation collection/selection; raw-state folding; reference/mapping; full attribute calculator; source geometry; fire-control/interval generation; speed metric; normalization/Handling; key serialization/cache lookup; ranking/reconstruction; memory/GC. Count calls and key cardinalities, not only elapsed time. Compare one-variable variants on the same original population, same partitions and 16 workers, including cold/warm behavior and per-worker participation. Possible savings from bypassing calculator rebuilds, geometry/timeline reuse or state mapping are **hypotheses** until measured; serialization, private cloning and low reuse can offset them.
