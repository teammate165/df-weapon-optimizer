## Model and evidence

The source-model audit pins dfttk data version `20261108-an94-bd-shop.1` and runtime `09f820e0d3ada199`. Enabled UI controls have 3–101 positions per context in the audit. UI positions define the finite research domain; programmatic continuous input can clamp without snapping. Mount selection changes available sliders and some references. Within a fixed context, slider effect tables can be precomputed at legal positions, including source conversion. Stacking and objective evaluation still combine their effects. Source numeric buckets include additions, multipliers and initial/reference behavior; the dedicated velocity path applies float32 conversion. Single/burst overlays, strongest-per-stat laser selection, panel response curves and order-sensitive folding defeat an unconditional sum of final attachment deltas. [Source trace and calibration audit](../weapon_calibration.md), [native stat reuse](../shared_stat_calculation.md), [price ingestion](../operation_prices.md).

Score uses default-normalized pattern, camera and kick losses with default weights 40/30/30, with a legacy multiplier-norm fallback for unsupported firing protocols. Pattern includes max horizontal displacement, vertical excursion and a step change at horizontal-speed thresholds. Camera and kick use norms. Magnitude is monotone in a component only while its sign stays fixed; caps, direction, extrema, reference replacement and differing protocol branches require per-target proofs. Handling rewards lower ADS and sprint-to-fire times in its normalized aggregate. Agility also rewards lower idle hip spread. Panel response curves are weapon/mode/target-specific and may flatten or change effective slope. No blanket order on raw stats follows. The proposed client-perception metric still needs calibrated scales, camera/sight measurements and region/patch verification. [Presets](../../tools/optimizer_presets.mjs), [response curves](../weapon_stat_response_curves.md), [perceived recoil proposal](../perceived_recoil_score.md).

## Research contract

Let `x` select an allowed item/default/empty at each active path and let `c` choose a legal position for each enabled control. A build is legal if the resolved mount graph, mode, locks, policies, calibration and any hard stat floors all hold. For one immutable catalog, prices, weapon, firing mode and objective version, evaluate final state `S(x,c)`, score `P(S)` (larger is better, e.g. negative recoil loss) and cost `K(x,c)`. Unknown fees/prices need explicit eligibility policy. Use native replay as the reference for feasibility and final result values.

1. Maximize P subject to K ≤ B.
2. Minimize K subject to P ≥ Pmin. This follows the handoff's equation without a budget cap. Report if the minimum exceeds B. A shared-budget product interpretation would add K ≤ B and needs confirmation.
3. Prototype balanced utility is U = P − λK, with finite fixed λ > 0 in score units per mode currency unit, and K ≤ B. Set λ before search. An optional hard minimum score needs a product decision.

These rules replace the moving threshold and candidate-dependent knee only in this research contract. Ties in the prototype accept any equal-value feasible witness; a production lexicographic Handling/cost/identity tie-breaker must participate in pruning or force continued search on equality. Outputs can coincide. Feasible-set emptiness is separate for each query.

Under these rules, whole-build dominance (higher/equal P, lower/equal K) preserves the three objective values; a Pareto frontier is sufficient but finding all its points is unnecessary. Existing strict recoil/Handling ranking needs additional tie dimensions. The default top-percentile gate has a separate population and identity contract that requires preserving multiplicity.
